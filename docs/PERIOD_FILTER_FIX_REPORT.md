# 🔧 ИСПРАВЛЕНИЕ ФИЛЬТРА "ПО ДНЯМ" - ELOM

## 🚨 **ПРОБЛЕМА**

**Ошибка:** Фильтр "По дням" в отчете по периодам не работал корректно  
**Симптомы:** 
- При выборе "По дням" возвращались данные, сгруппированные по месяцам
- Количество записей было одинаковым для "По дням" и "По месяцам"
- Формат дат был неправильным (YYYY-MM-01 вместо YYYY-MM-DD)

---

## 🔍 **ДИАГНОСТИКА**

### **Найденная проблема:**

**❌ Неправильная реализация для SQLite**
- **Место:** `reports/views.py:133`
- **Причина:** Замена `TruncDate` на `TruncMonth` для SQLite совместимости
- **Результат:** Фильтр "По дням" работал как "По месяцам"

### **Код до исправления:**
```python
# Используем TruncMonth для SQLite совместимости
g = TruncMonth("date")  # SQLite не поддерживает TruncDate
data = (
    qs.values(period_field=g)
    .annotate(
        purchases=Count("id"), 
        total_amount=Coalesce(Sum("total_amount"), Value(0, output_field=models.DecimalField()))
    )
    .order_by("period_field")
)

rows = []
for row in data:
    key = row["period_field"].strftime("%Y-%m-%d" if period == "day" else "%Y-%m")
    # ❌ Проблема: period_field всегда был месяцем, даже для period="day"
```

## ✅ **ИСПРАВЛЕНИЕ**

### **Новая реализация с правильной SQLite поддержкой:**

```python
if period == "day":
    # Для SQLite используем date() функцию вместо TruncDate
    from django.db.models import F
    from django.db.models.functions import Cast
    from django.db.models import CharField
    
    # Группируем по дате как строке для SQLite совместимости
    data = (
        qs.extra(select={'date_str': "date(date)"})
        .values('date_str')
        .annotate(
            purchases=Count("id"), 
            total_amount=Coalesce(Sum("total_amount"), Value(0, output_field=models.DecimalField()))
        )
        .order_by('date_str')
    )
    
    rows = []
    for row in data:
        rows.append({
            "period": row["date_str"],  # ✅ Реальная дата (YYYY-MM-DD)
            "purchases": int(row["purchases"]),
            "total_amount": float(row["total_amount"] or 0)
        })
else:
    # Для месяцев используем TruncMonth
    g = TruncMonth("date")
    data = (
        qs.values(period_field=g)
        .annotate(
            purchases=Count("id"), 
            total_amount=Coalesce(Sum("total_amount"), Value(0, output_field=models.DecimalField()))
        )
        .order_by("period_field")
    )

    rows = []
    for row in data:
        key = row["period_field"].strftime("%Y-%m")  # ✅ Реальный месяц (YYYY-MM)
        rows.append({
            "period": key,
            "purchases": int(row["purchases"]),
            "total_amount": float(row["total_amount"] or 0)
        })
```

## 🔧 **ТЕХНИЧЕСКИЕ ДЕТАЛИ**

### **SQLite совместимость:**
- **Проблема:** SQLite не поддерживает `TruncDate` функцию
- **Решение:** Использование `date(date)` функции SQLite
- **Реализация:** `qs.extra(select={'date_str': "date(date)"})`

### **Условная логика:**
- **period="day"** → Используется SQLite `date()` функция
- **period="month"** → Используется Django `TruncMonth()`
- **Результат:** Корректная работа в обеих режимах

### **Производительность:**
- ✅ **Оптимизированные запросы** - используется `extra()` для SQLite
- ✅ **Правильная группировка** - по реальным датам/месяцам
- ✅ **Эффективная сортировка** - `order_by('date_str')`
