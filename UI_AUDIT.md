## 1. Метод и покрытие

Оснастка: `tools/ui-audit/audit.mjs` (сохранена в репо, F-315). На каждом экране:
скриншот + ошибки консоли + упавшие запросы + **WCAG-сканер контраста по фактически
отрендеренным парам «фон↔текст»**.

> **Важно про сканер.** Первая версия парсила `getComputedStyle().color` регуляркой как `rgb()` и
> выдала **ложные 1.15:1** — Tailwind v4 отдаёт цвета в `oklab()/oklch()`, регулярка читала `0.94`
> как красный канал. Сканер переписан на **canvas** (заливка фон → цвет поверх → чтение пикселя):
> корректно для любого цветового пространства И для альфа-композитинга. Все числа ниже — с
> исправленного сканера. Ложные находки в отчёт не попали.

## 3. Находки

### 🟠 H-1 · Подписи `.btn-outline` практически невидимы — 1.49:1 (light) / 1.74:1 (dark)

| | |
|---|---|
| **Экран** | 67 из 104 (почти все списки: закупки, списания, остатки, объекты, материалы, сотрудники, поставщики, единицы, инструменты, RBAC, архив…) |
| **Роль/тема/вьюпорт** | admin (все роли), **обе темы**, десктоп + мобильный |
| **Что не так** | Текст «Экспорт» и подписи прочих outline-кнопок отрисованы цветом `base-content` с **альфой 0.2** → **1.49:1** в светлой, **1.74:1** в тёмной (норма 4.5:1) |
| **Почему мешает** | Пользователь физически не читает подпись действия. Для бригады в поле — кнопка без читаемой подписи бесполезна |
| **Severity** | **HIGH** |

**Причина (класс, а не случай).** Базовое правило DaisyUI задаёт вменяемый дефолт
`--btn-fg: var(--color-base-content)`, но `.btn-outline` его **перекрывает**:

```css
.btn-outline:not(...) { --btn-fg: var(--btn-color); --btn-border: var(--btn-color) }
```

`--btn-color` определяется **только цветовыми модификаторами** (`.btn-primary` → `--btn-color: var(--color-primary)` и т.д.).
У «голой» `.btn-outline` модификатора нет → `var(--btn-color)` невалиден → `--btn-fg` рушится.

Масштаб класса (проверено grep, не предположено): **21 «голая» `.btn-outline`** против **2** с модификатором.
Затронуты: ExportButton, WriteOffs/List, RBAC/List, Tools/List, ArchivePeriods, PurchaseInfo (3 circle-кнопки),
WriteOffByBalanceForm и др.

**Фикс (централизованный, без модификаторов по местам):** дать `--btn-fg`/`--btn-border` корректный
**fallback** на уровне CSS — `var(--btn-color, var(--color-base-content))`. Одно правило чинит все 21.

### 🟠 H-2 · Медный `text-primary` на тёмных поверхностях — 3.51:1

| | |
|---|---|
| **Экран** | dashboard, rbac/roles, tools, objects/info, reports (5+ экранов, 25+ вхождений) |
| **Роль/тема/вьюпорт** | admin, **тёмная тема**, десктоп |
| **Что не так** | `rgb(182,86,22)` (медь, dark `--color-primary`) на `rgb(22,29,34)` = **3.51:1** при норме 4.5 для 11–14px. Ссылка `link-primary` на base-100 — **3.76:1** |
| **Почему мешает** | Медью выделено самое важное: значения статистики, бейджи ролей, mono-числа, ссылки. Именно акцент читается хуже всего |
| **Severity** | **HIGH** |

Затронутые классы: `span.stat-value`, `span.badge.badge-primary`, `span.font-mono.font-bold.text-primary`,
`div.badge.badge-primary` («После ремонта»), `a.link.link-primary` («Открыть карту»).

**Причина.** F-276 подбирал медь под **белый-на-меди** (заливка кнопки) — там она обязана быть тёмной.
Но **медь-как-ТЕКСТ на тёмном фоне** требует обратного (светлее). Один токен обслуживает два
противоположных сценария.

**Фикс:** отдельный токен для «медь как текст на тёмной поверхности» (светлее, ≥4.5:1), заливка кнопок
остаётся на текущем `--color-primary`. Закрепить стражем.

### 🔵 L-1 · Тач-цель 24px на мобильном
`button.btn.btn-xs.btn-ghost` — высота **24px** при норме ≥44px (3 вхождения). Мелкие иконочные действия
в списках. **Фикс:** правило минимальной тач-высоты для `.btn-xs` на мобильном (в проекте уже есть
`.btn` ≥44px на мобильном — `btn-xs` из него выпал).

### 🔵 L-2 · Псевдо-кнопка `div.btn`
`ExportButton.vue:3` — интерактивный контрол сделан `<div class="btn">`, а не `<button>`.
Смягчающее: есть `role="button"` + `tabindex="0"`, дропдаун открывается по фокусу — с клавиатуры
работает. Но `:disabled` на `<div>` **семантически бессмыслен** (не блокирует, роль не меняет);
блокировка держится только на классе `btn-disabled` (`pointer-events:none`).
**Класс проверен:** это **единственная** псевдо-кнопка в проекте (grep по `div/span` с классом `btn`).
**Фикс:** заменить на `<button type="button" :disabled>`.

## 5. Не покрыто (честные ограничения)

Аудит статический — экраны открывались и снимались, без взаимодействия и **без мутаций в проде**:

1. **Пустые состояния** — ни на одном экране не встретились (везде есть данные), поэтому
   «человечность» пустых экранов **не проверена**. Нужен отдельный прогон с фильтром «ничего не найдено».
2. **Интерактивные состояния** — hover / focus-ring / открытые дропдауны и модалки / тосты
   не захватывались (только загрузка страницы).
3. **Обратная связь и подтверждения** необратимых операций (закрытие периода, удаление) не
   проверялись — это требует мутаций на проде.
4. **PWA/офлайн** — баннер офлайна, предложение обновления, блокировка мутаций офлайн не воспроизводились.
5. **Роли** — захвачены роль-специфичные экраны; контраст по ролям **не дублировался** намеренно
   (пары «фон↔текст» от роли не зависят).

Пункты 1–4 — кандидаты на отдельный интерактивный прогон, если нужно закрыть и их.
